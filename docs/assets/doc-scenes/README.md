# Documentation scenes

Small MoonRay scenes used to make the images in the attribute reference, and
for you to download and experiment with, along with the textures, scripts and
other files used to make them. Each scene object type has its own folder,
following the layout of `user-reference/scene-objects`:

```
doc-scenes/
  <group>/<Class>/             # for example lights/SpotLight/
    manifest.json              # the images and videos to render from the scenes
    scenes/*.rdla              # the scenes behind the images
    textures/                  # textures and other files the scenes use
    scripts/                   # optional: scripts that generate the files above
```

The scenes can be written by hand or generated by a script. Only
`manifest.json` and the scenes and files it uses are needed to render the
images. Scenes shared by several images, such as a base scene that the others
vary, can go directly in the folder.

By convention, `scenes/<attribute>_<value>.rdla` is the scene behind the image
`<attribute>_<value>.jpg` on the object's reference page, and a comment at the
top of each scene says what it shows.

## How the scenes get onto the reference page

The object's data file, `docs/_data/user-reference/scene-objects/<group>/<Class>.yml`,
connects the folder to the page:

- `doc_scenes: <group>/<Class>` adds an "Example scenes" section at the end of
  the page, which lists everything in the folder except JSON and Markdown
  files for download.
- Each image, in `gallery:` or in an attribute's `images:` under
  `attributes:`, can have a `scene:` path, relative to the object's folder,
  which adds a download link for that scene under the image.

The images themselves are rendered into
`docs/assets/images/user-reference/scene-objects/<group>/<Class>/` by
[`cmd/generate_doc_images`](../../../cmd/generate_doc_images/README.md), from the
scenes listed in `manifest.json`.

## Rendering a scene

Scenes refer to other files with paths relative to the object's folder, so
render from there:

```bash
source /path/to/openmoonray/scripts/setup.sh
cd <group>/<Class>
moonray -in scenes/<scene>.rdla -out <scene>.exr
```

## Adding scenes by hand

1. Put the scenes in `scenes/`, and the textures and other files they use
   alongside them, such as in `textures/`. Refer to those files with paths
   relative to the object's folder.
2. List the images and videos to render in `manifest.json` (see the
   [manifest format](../../../cmd/generate_doc_images/README.md#manifest)).
3. In the object's data file, set `doc_scenes` and add `images:` entries with
   `scene:` paths, as described above.
4. Render the images (see [Rendering the images](#rendering-the-images)).

When you remove a scene, also remove its entries from `manifest.json` and the
data file, and delete its image: `generate_doc_images` doesn't delete images.

## Generating scenes with a script

A script in the object's `scripts/` folder can generate the scenes instead,
for example with the `scene_rdl2` Python API. It should:

- write the scenes into `scenes/` in the folder above it, so that it can be run
  from any directory
- write `manifest.json`
- optionally, write the `images:` entries of the data file, under a comment
  saying which script generated them, so that they aren't edited by hand
- remove scenes and images it no longer generates

Each script's `--help` describes its options. Scripts that use `scene_rdl2`
need a Python of the version its bindings were built against (3.9 for current
releases), with the bindings on `PYTHONPATH`:

```bash
source /path/to/openmoonray/scripts/setup.sh
export PYTHONPATH=/path/to/openmoonray/python/lib/python3.9:$PYTHONPATH
python3 <group>/<Class>/scripts/<script>.py
```

Then render the images.

## Rendering the images

[`cmd/generate_doc_images`](../../../cmd/generate_doc_images/README.md) reads
`manifest.json` and writes the images and videos:

```bash
cmd/generate_doc_images/generate_doc_images -c <Class>
cmd/generate_doc_images/generate_doc_images -c <Class> --attr <attribute>,<attribute>
```

Rendering takes a while, so re-render only the attributes you changed, with
`--attr`. See the `generate_doc_images` README for requirements and how
unchanged renders are detected.
